# 英語学習ゲーム「Calorie Quest: Speak & Snack (仮)」仕様書

## 1. 概要
本プロジェクトは、英語学習のモチベーション維持を目的とした軽量な学習ゲームソフトウェアである。プレイヤーは英語の問題を解くことで「その日食べても良いお菓子のカロリー上限（カロリーポイント）」を獲得し、現実世界でのご褒美を楽しむことができる。
正確な発音習得を重視しつつ、Rust言語をベースとした高速かつ軽量な動作を実現する。

## 2. システム要件・技術スタック
* **開発言語 (バックエンド/コアロジック):** Rust
* **フレームワーク:** 
  * **Tauri:** 超軽量なデスクトップ/モバイルアプリ構築のため。フロントエンドの描画にOSの標準WebViewを利用し、ゲームエンジンを使うよりも圧倒的にバイナリサイズとメモリ使用量を削減可能。
  * フロントエンドはHTML/CSS/TypeScript(React等)を使用し、Web Speech APIを活用することで、重い音声認識モデルを同梱せずに軽量な発音判定を実現する。
* **データベース:** SQLite (Rustの `rusqlite` または `sqlx` を使用。ローカル完結で軽量)

## 3. コア機能仕様

### 3.1. カロリー報酬（ご褒美）システム
学習した問題の難易度と量に応じて、その日の「獲得カロリーポイント」が加算される。

* **ポイント換算例:**
  * **難易度・低 (英単語):** 10問正解 = 20kcal
  * **難易度・中 (短いフレーズ/文法):** 10問正解 = 40kcal
  * **難易度・高 (慣用句/長文発音):** 10問正解 = 100kcal（クッキー2枚分に相当）
* **減算:**
  * 記入問題でヒントの単語を開示すると、開示1語につきその問題の獲得カロリーが半分になる。
* **機能:**
  * 今日の獲得カロリーと、それに相当する代表的なお菓子のアイコンが画面上にプログレスバーとして表示される。

### 3.2. 出題形式と学習システム
多様なアプローチで英語を定着させる。

1. **選択問題 (Multiple Choice)**
   * 英単語の意味、文法の適切な穴埋めなどを4択から選ぶ。
   * テンポよく回答でき、基礎的なカロリーポイントを稼ぐ用途。
2. **記入型問題 (Fill-in-the-blank / Typing)**
   * 提示された日本語訳に合うように、キーボードで英単語やフレーズをタイピングする。
   * スペルの正確な記憶を促す。
3. **発音・スピーキング問題 (Pronunciation - 重点項目)**
   * **機能:** ネイティブの音声データ（または高精度なTTS音声）を再生し、プレイヤーがマイクに向かってリピートする。
   * **判定:** 音声認識APIを利用し、認識されたテキストと正解テキストの一致度、および発話の流暢さ（認識にかかった時間等）からスコアを算出。
   * **フィードバック:** 間違えやすい子音や母音（RとL、thなど）が含まれる単語では、発音のコツを図解で表示する。

## 4. 追加おすすめ機能（学習効果・継続性アップ）

仕様に追加提案する、学習向け拡張機能です。

### 4.1. 忘却曲線ベースの復習システム (Spaced Repetition System: SRS)
* 一度間違えた問題や、発音判定でスコアが低かった問題を、記憶が薄れるタイミング（翌日、3日後、1週間後...）で自動的に再出題する。
* 復習問題をクリアした場合は、**通常の1.5倍のカロリーポイント**が付与されるなど、復習を促すインセンティブを設ける。

### 4.2. カスタム「お菓子図鑑」とカロリー家計簿
* プレイヤーが自分のお気に入りのお菓子とそのカロリーを登録できる機能。
  * 例：「近所のケーキ屋のショートケーキ (350kcal)」を目標に設定。
* 目標のお菓子を設定すると、「あと〇〇問単語を解けば食べられる！」という具体的な数値が画面に表示され、モチベーションが飛躍的に向上する。

### 4.3. 連続学習（ストリーク）ボーナスとチートデイ
* 毎日連続で学習すると「ストリーク」が貯まる。
* 7日連続学習を達成すると、週末に「チートデイチケット（無条件で+300kcalボーナス）」が発行されるなど、毎日ログインする理由を作る。

## 5. UI/UX の方向性
* **デザイン:** カフェや洋菓子店をモチーフにした、温かみのある落ち着いたデザイン。
* **動作の軽快さ:** Rustの強みを活かし、アプリの起動時間ゼロ秒台、画面遷移のラグなしを目指す。
* **サウンド:** 正解時には「サクサク（クッキーをかじる音）」など、お菓子にちなんだ心地よいSE（効果音）を採用する。

## 6. データモデル（概念設計）

* **User (ユーザー情報)**
  * 累計学習日数, 現在のストリーク数, 本日の獲得カロリー
* **Question (問題データ)**
  * ID, タイプ(選択/記入/発音), 英語テキスト, 日本語訳, 難易度(低/中/高), 音声ファイルパス
* **LearningHistory (学習履歴)**
  * ユーザーID, 問題ID, 正誤, 発音スコア, 最終学習日時, 次回出題予定日時(SRS用)
* **SnackDatabase (お菓子データベース)**
  * 名前, カロリー, アイコン画像パス
